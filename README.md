# web-pentest — AI 渗透测试执行 skill

> 一句话：**AI 是测试执行者，这套机制是套在它身上的护栏，你是最终裁决者。**
> 它不承诺 AI 不会漏——它承诺：**漏了能被对账和审计抓出来。**

## 为什么需要这套机制

把判断全交给 AI，AI 必然产生幻觉、偷懒、编造——这不是 bug，是生成式模型的结构性属性：它只会"接续最合理的文本"，不会"核对事实"；它没有"做过"的记忆，只有"上下文里写着做过"；它把自己的输出当事实读；错误没有即时代价。

所以这个 skill 的思路不是修 AI 的品性，而是**改结构：让每种失败模式都撞上一套专门的对冲机制**。

## 工作流程（AI 在每个阶段干什么）

**阶段 0 · 启动** — AI 盘点你给的信息（目标/授权/凭据），检查接线（Stop hook 装没装、工具齐不齐），建立工作目录与进度状态文件。

**阶段 1 · 侦察：建分母** — AI 把目标的全部接口盘成一张「接口 × 12 维度」追踪矩阵。这张表是整个测试的分母：**空格即遗漏**，后续所有对账都对着它。

**阶段 2 · 灰盒** — 拿到组件信息就查 CVE（四态判定：可利用/不可利用/存疑/未查证，不许冒充）；拿到代码就查内置账号、隐藏路由（网关路由表 × 前端 JS 强制 diff）。

**阶段 3 · 黑盒：主战场** — AI 逐格打 payload，覆盖 14 类注入入口。每一枪都 curl 落盘 + 读实测响应；机器三查（证据存在/非空/非 WAF 拦截页）通过才能打勾。阶段切换时 Stop hook 由客户端强制注入闸门提醒——AI 跳不过去。

**阶段 4 · 确认** — 每个结论必须标判断方式（实弹/代码层/文档/推断 四分类，不许冒充）；测过但没发现的记 U 项——"没发现"也要有实测依据。

**阶段 5 · 报告与定稿** — 每条漏洞 7 字段，实测响应是硬要求（不是"预期返回"的转述）；定级带反方论证（为什么不是更高级）；双轨终审（fresh-context 结构审计 + 语义校验）；终止门五条机器检查通过才给定稿回执，报告哈希入锚。够不够交付，留给人裁。

## 三个不变量（贯穿全程）

1. **状态外置** — 记忆在文件不在对话；断点续传靠磁盘对账，不靠 AI 说"我记得测过了"。
2. **过阶段必过闸** — 每次阶段切换都被拦下对账：矩阵空格清了没有、未闭合项有没有合法理由码（封闭集合，"时间不够"非法）。
3. **人只裁三件事** — 红线操作授权 / 定级争议 / 终版放行；其余全是机器判据 + AI 执行。

## 护栏总览：失败模式 → 对冲机制

| AI 的失败模式 | 对冲机制 |
|---|---|
| 幻觉（编造漏洞/响应） | 实测响应硬要求、证据形态强制 |
| 偷懒（模式续写"已测无异常"） | 终止门空格检查、封闭理由码 |
| 无状态编造（"我记得测过"） | 状态外置落盘、续传对账 |
| 自反馈锚定（把自己的话当事实） | fresh-context 审计（不带记忆的眼睛） |
| 问它"确定吗"= 再采样一次 | 机器 grep/计数/哈希（不生成的才不会编） |

## 安装

1. 将 `web-pentest/` 目录整体复制到你的 skills 目录（ZCode：`~/.agents/skills/web-pentest/`；其他客户端放各自 skills/个人规则目录）。
2. 推荐：接线 Stop hook（阶段闸门的物理强制层，安装见 `web-pentest/flow/setup.md` §7）。依赖客户端支持 Stop hook；不支持时该层失效，其余机制不受影响。
3. `pentest-report-check/`（终审"语义校验"轨道的配套 skill）已包含在本包——与 `web-pentest/` 一起复制到 skills 目录即可。只装 web-pentest 也能跑，语义校验轨道会如实标注"未执行"，不阻塞流程。

## 使用

对 AI 说"对 <目标> 做渗透测试 / 安全测试"即可触发。完整规则、红线与授权预设见 `web-pentest/SKILL.md`。
